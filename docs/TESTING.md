# Testing EDCM

The automated suite checks journal processing, carrier outputs, settings, service boundaries, authentication, controller behavior, and real Tk rendering. It uses synthetic journals and temporary application data. It does not require the game, personal journals, credentials, or live services.

Production behavior is unchanged by this test addition. Passing regression tests and known-defect diagnostics are separate selections. The diagnostics express desired behavior that the application does not yet satisfy; see [the defect report](TEST_DEFECTS.md).

## Install and run

Use Python **3.12.7**, matching the executable builds and CI. From the repository root, create/activate a virtual environment and install:

```console
python -m pip install -r requirements-dev.txt
python -m pytest -m "not known_defect"
```

Tests run only in the environment where you launch pytest. On Windows, use the command above; there is no Docker, WSL, or Linux test run to launch. You do not need to validate another operating system.

Each pytest run creates a fresh private directory under the repository's ignored `.cache/pytest/run-<random>/` directory and removes that run's directory when the session closes. On Windows, sandbox and interactive processes can share the `USERNAME` environment variable while running as different accounts. Reusing a `pytest-of-<username>` directory then fails because its permissions belong to the account that created it. A separate parent for each run avoids this collision without changing existing permissions.

The suite honors explicit `--basetemp` and `PYTEST_DEBUG_TEMPROOT` overrides. If you previously set `PYTEST_DEBUG_TEMPROOT` to the shared directory, remove that override to use the isolated default:

```powershell
Remove-Item Env:PYTEST_DEBUG_TEMPROOT -ErrorAction SilentlyContinue
python -m pytest -m "not known_defect"
```

For debugging, an explicit `--basetemp` retains temporary files after the run. Choose a dedicated writable directory: pytest clears that directory at startup, so do not share it between simultaneous runs or point it at personal files. Existing inaccessible directories do not need to be deleted, and administrator access is not required for the default setup.

If you launch tests directly on a Linux host without a display, install Xvfb, xauth, and Tk support, then run:

```console
sudo apt-get install xvfb xauth python3-tk
xvfb-run -a python -m pytest -m "not known_defect"
```

GUI tests use actual Tk and tksheet widgets. Missing Tk/display support is a setup failure, not a skipped test. The fixtures select the dummy tray backend before importing the application.

Useful selections:

```console
python -m pytest -m "not known_defect and not gui"
python -m pytest -m "gui and not known_defect"
python -m pytest -m known_defect
python -m pytest tests/test_journal_resilience.py -m "not known_defect"
python -m pytest -m "not known_defect" --cov --cov-report=term-missing --cov-report=html:test-results/htmlcov --cov-report=xml:test-results/coverage.xml --junitxml=test-results/regression.xml
```

Prefix GUI-containing commands with `xvfb-run -a` only when running on a Linux host without a display. Running pytest without `-m` includes known defects and is expected to fail while those defects remain. Diagnostics use ordinary failures, not `xfail` or `skip`.

## Test organization and assertions

- `tests/journal_helpers.py` builds fresh, complete synthetic events with fixed timestamps and provides controlled append/replay helpers.
- Journal and model tests exercise initial reads, incremental updates, partial writes, rotation, cache resume, missing/corrupt records, account mixing, and table-facing outputs.
- Service tests replace HTTP responses, credential storage, clocks, schedulers, and webhooks at application boundaries.
- Controller tests use bounded workers and controlled callbacks. GUI integration tests connect the real model, view, and selected controller methods without launching persistent services or an unrestricted mainloop.
- `gui` marks real-widget tests; `integration` identifies tests crossing application layers; `known_defect("ID")` identifies a reproduced defect in the report.

Use exact assertions for selected input/output values and meaningful behavior: the correct carrier balance, independent owners, a preserved note, one notification, or one consumption of an appended record. Prefer relationships for layout and timing. Avoid full UI text snapshots, exact font metrics, incidental implementation call counts, and snapshots of entire model objects. Expected values must not be generated by calling the method under test.

For damaged journals, require preserved valid state, continued processing of later valid events, and stable repeated polling. A deleted digit may still produce plausible valid data; tests cannot reconstruct what was originally written. Mixed files must not create new account associations from ambiguous event ordering; independently established ownership and carrier-ID data should survive.

Tests use temporary settings/config/notes/cache paths. `.env` loading is disabled before application imports. Unexpected network, keyring, browser, clipboard, sound, or watcher operations fail the test even if application code catches the raised exception. Explicitly replace the relevant boundary in each test. Fake clocks and schedulers instead of sleeping; collect worker exceptions through futures and check Tk callback failures. Each test has a 60-second timeout.

Pytest captures Python streams (`--capture=sys`) so it does not replace native file descriptors used by Tk. This avoids Windows Tcl/theme-loading errors observed when consecutive GUI diagnostics fail under file-descriptor capture. CI's outer log capture still records native process output.

## GitHub Actions

The regression and diagnostic workflows each run on pushes, pull requests, and manual dispatch with a Windows and Ubuntu matrix using Python 3.12.7. Each job runs the same test selection natively on its own runner; Ubuntu jobs use Xvfb for Tk. GitHub Actions runs both environments independently of the operating system of the computer that pushed the commit. Local pytest still runs only on its current host. No repository secrets are required. Existing executable and release workflows are unchanged.

Configure both regression checks as required in repository branch protection:

- `Regression (windows-latest, Python 3.12.7)`
- `Regression (ubuntu-latest, Python 3.12.7)`

Leave `Diagnostics (...)` checks non-required. Their red status is intentional while documented defects remain; there is no `continue-on-error` to conceal it. Adding these workflows does not itself alter branch protection.

Artifacts contain JUnit reports and captured logs. Regression artifacts also contain XML and HTML branch coverage. There is no initial coverage percentage gate, and diagnostic coverage is not merged into regression coverage. The job summary distinguishes test failures from setup, collection, configuration, and no-tests-collected errors, lists failed test IDs, and highlights passing diagnostics for review.

### Verified baseline

The initial suite was validated on Windows with freshly installed declared dependencies on Python 3.12.7: 311 regression tests and 28 subtests passed. The diagnostic selection reproduced 51 failures covering 23 defect IDs, with no setup or collection errors.

Hosted GitHub Actions runs begin after these changes are pushed; local validation does not change repository settings.

## Maintaining diagnostics

1. Reproduce the failure with a minimal deterministic case and a valid control input.
2. Assert the desired behavior directly. Do not merely assert that the current crash occurs.
3. Mark only the failing cases with a defect ID and add severity, expected/observed behavior, reproduction command, and code references to the defect report. Keep passing parameters in regression coverage.
4. After a production fix, run the diagnostic in your current environment. Remove its marker when it passes and retain the regression test; update the report to record the resolution. CI then verifies the promoted test on both Windows and Ubuntu, without requiring local cross-platform runs.

Do not move a failing regression into diagnostics merely to make CI green. First establish whether it is a test defect, a dependency/setup problem, or a reproducible application defect.

## Existing manual and archived tests

Applicable journal, column-sizing, and UI-thread tests were migrated into `tests/`. Tests for absent route and hidden-column APIs are preserved under [legacy_tests](../legacy_tests/README.md), outside pytest discovery. The original interactive `fake_journal_test.py` launcher and `drop_test.py` are not CI tests; their useful behaviors are covered through finite, deterministic integration tests. The suite never depends on the ignored `fake_journals` directory.
